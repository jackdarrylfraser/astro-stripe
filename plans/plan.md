# Plan: Astro + Vercel + Stripe (subscription-gated pages)

## Approach
Astro in SSR mode (`output: 'server'`, `@astrojs/vercel` adapter). Public pages are written in markdown and should be hosted on a private vercel static hosting and checked as middleware via a serverless function.

One Stripe subscription product via a Stripe Payment Link to hosted Checkout. There are no app accounts: the normalized email used in Stripe Checkout is the unique identity. After purchase, the server verifies the Checkout Session, stores the subscription in Upstash Redis, and creates a Redis login session for that email. Later logins use a magic link sent to that email. The app checks Redis for subscription status and uses Stripe as the source of truth when the cached record is missing or stale. Logging out revokes the current Redis login session and clears the browser cookie; it does not delete the subscription record. Customers manage subscriptions through a "Manage subscription" link that redirects to Stripe's hosted Customer Portal; do not build a separate subscription-management page. The redirect endpoint leaves Redis unchanged; a verified Stripe `customer.subscription.deleted` webhook removes the matching subscription entry after cancellation takes effect.

## Architecture
- Auth: verified Checkout creates the first login session for its email; subsequent logins use one-time magic links. Redis stores expiring login sessions and one-time magic-link tokens; logout deletes the current login session. No user/account records are created.
- Data: Upstash Redis stores subscription records keyed by normalized email, login sessions, one-time magic-link tokens, and Checkout Session idempotency records.
- Stripe: Product + recurring Price and a Payment Link configured for subscriptions; a server completion route verifies paid Checkout Sessions and writes subscription and login-session records; webhooks keep subscription records synchronized and remove the matching Redis subscription only after Stripe reports it deleted. When Redis has no fresh subscription state, check Stripe before granting access. The manage-subscription redirect endpoint uses the validated login session to find the Stripe customer, creates a Stripe-generated Billing Portal session URL, and redirects to the Portal without changing Redis.
- Gating: Astro middleware (`src/middleware.ts`) resolves the email from the Redis-backed login session and checks subscription status in Redis, refreshing from Stripe when needed; it redirects unauthenticated visitors to sign-in and inactive subscribers to `/pricing`.
- Deploy: Vercel project from GitHub (Bun detected via `bun.lock`; Vercel installs with Bun, set Install Command `bun install` if needed; SSR functions still run on the Node.js runtime, so avoid Bun-only APIs like `Bun.file` in app code); env vars per environment; Stripe test mode on Preview, live on Production.
